# Native Create deployer evidence

Date: 2026-10-19, UTC+08:00. Advances CRAFT-03–05 and ADAPT-05; full port
and integrated acceptance remain unfinished.

## Native completion boundary

The pinned Create 6.0.10-mc1.21.1-performance-v6 BeltDeployerCallbacks.whenItemHeld
selects the current recipe and invokes activate during its native retraction cycle.
The optional adapter scopes that caller through output storage and tool handling.
Direct activate calls, unrelated fake-player actions and transient sequenced recipes
cannot acquire standalone deploying evidence. Only the actual unique registered
recipe object, live assigned machine and online non-fake beneficiary are admitted.

RecipeApplier rolls the actual single input and invokes its native remainder callback.
PREPARED admission copies those results before the transport holder stores them.
Deployer output uses the existing exact depot/belt checks, including complete pending
queues, retained input, accepted native overflow and component-sensitive quantities.
The source is the deployer rather than the press. Empty random rolls may complete
native input/tool consumption but contribute no primary-output progress.

The deployer updates its held tool only after output insertion. Confirmation waits
for this update and requires both verified transport storage and the complete tool
inventory delta. ToolData retains defensive pre-operation hand/inventory copies and
the actual selected recipe's keep-held-item policy. Existing observation constructors
and basin/fluid encoding remain compatible.

Retained tools preserve the exact hand and inventory. Damageable tools use the actual
native hurtAndBreak callback and resulting hand, including unbreaking/break semantics;
the callback is never re-run for verification. Consumable tools remove one exact item
and retain the actual native remainder in the hand, player inventory or accepted
drop. Verification compares all inventory contents and the expected hand separately,
so moving an equivalent item into a different hand state cannot mask a change.
Only exact captured live drop entities count; nearby items do not supply evidence.
Native empty-remainder drop calls return null and have no storage requirement.

Changed input/tools, rejected or changed drops and incomplete storage remain
unconfirmed. If a native tool remainder callback throws after output insertion, the
original exception propagates and the prepared operation becomes INTERRUPTED, without
quest credit. Journal reconciliation cannot reprocess input or consume the tool.

## Validation

DeployerRuntimeAudit uses motor-powered native depot and connected-belt cycles.
Twenty-six checks cover:

- Native power/player initialization; assigned, unassigned and offline attribution.
- Actual primary/random/component results and exact retained input/tool quantities.
- Defensive serialized ToolData and duplicate/reopened absolute task projection.
- Missing or wrong tool and empty random results without primary progress.
- Keep-held-item policy, actual tool damage and last-durability break.
- Remainder replacement of the hand, separate inventory storage and full-inventory drop.
- Rejected drop or changed components, admission-time tool/input mutation.
- Native remainder exception after output storage and unrelated activate exclusion.
- Connected belt pending output storage without flushing queues.

Both NeoForge 21.1.233 and 21.1.248 also run 165 existing Create checks. Create-absent
regression, ordinary clean builds, separate retained JARs and exact provider/source/
log/package hashes are recorded in create-deployer-validation-2026-10-19.json.

Native testing found that Create attempts to drop even an empty tool remainder.
The observer now distinguishes an empty attempt from rejected nonempty storage.
Persisted drops from an earlier synthetic run also contaminated a legacy press
quantity check; affected fixtures now clear their own item entities at entry/exit.
No production process, data or provider native behavior was changed.

Fan processes and sequenced assembly, all required machine-specific kill/inventory
rollback cases, wider party/repeat/offline/reconnect/financial backup acceptance,
logging operations, legacy provenance, supported Paradigm inbound formatting and
physical VR/non-VR integrated migration remain open. No production deployment occurred.
