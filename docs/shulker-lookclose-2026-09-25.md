# Shulker LookClose response

Implementation base: `827736c`. Scope follows [the ecosystem guide](neoforge-ecosystem-replacements-2026-09-22.md).

## Native behavior

The original LookClose calls the Shulker peek setter while following a physical player target. The port now applies that response to the actual Shulker NPC entity. The amount is `max(0, 100 - 4 * floor(distanceSquared))`: one block gives 96, two blocks gives 84, and five or more blocks gives 0. Clamping happens before narrowing to an integer/native byte, including very large configured look ranges. This retains the original distance response without its negative-byte overflow beyond five blocks.

The first response initializes native armor even when the entity already has the requested raw amount. Subsequent unchanged amounts do not repeat the native setter, sound or game event. Changed amounts use the native setter's synced data, covered-armor modifier and container game events. A narrow mixin suppresses only the open/close sound calls made by a quiet response. It never temporarily changes the entity's silent flag, so event listeners observe the real flag and their own changes survive.

Native requests outside this quiet scope retain vanilla behavior. The mixin records every setter request, including repeated amounts. A quiet setter's final metadata write is conditional on its request still being current: a game-event callback that disables/despawns LookClose or issues a newer native request cannot be overwritten by the older pending response. Nested ordinary requests retain their own sound. This does not change the ordering of ordinary vanilla setters or provide a global transaction for arbitrary external metadata edits.

## Ownership and configuration

The response is temporary. Target loss, disabling, changing to per-player mode, navigation suppression, removal and despawn release its exact owned state. Release restores the captured baseline only if both the native request revision and raw amount still belong to that response. Later native requests, including the same value, survive release. Direct metadata changes observed before release also invalidate ownership. If physical looking continues on another tick, it captures a newer external amount as the baseline before applying the distance response again.

ShulkerTrait supplies its configured peek as the initial baseline regardless of trait execution order. Changes to that configuration during looking update the baseline without fighting the active response; release uses the latest configuration, including a repeated explicit value. A configuration request received after a native request supersedes that earlier baseline. Configured values remain the persisted values. The Java setter now rejects values outside 0–100 atomically; the existing command already enforced that range. Invalid legacy saved integers remain stored and are clamped only when sent to the native entity.

Appearance changes track the actual cosmetic entity so a replacement receives its configured peek. LookClose itself retains the original actual-entity restriction: a cow disguised as a Shulker does not acquire the physical response. Per-player look mode controls private rotations and does not introduce private shell states.
