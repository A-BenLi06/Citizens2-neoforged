# Remaining Citizens work

This is the current command and acceptance checklist for Minecraft 1.21.1. The September 13 audit contains historical gaps; later follow-ups supersede those rows. See the [ecosystem scope](neoforge-ecosystem-replacements-2026-09-22.md) for provider ownership.

[Interactions remains an independent NeoForge mod/JAR](independent-interactions-jar-2026-10-04.md), with dependency Interactions → Citizens. Its dedicated artifact now includes the release version in its own manifest. This packaging follow-up changes no gameplay classes/resources and leaves both Citizens artifacts byte-identical to the preceding validated build.

All 37 historically missing 1.21.1 `/npc` command names have entry points. Entry-point coverage is not behavior parity, and the historical missing-command count must not be used as today's backlog or a completion percentage.

A read-only declaration scan of the checked-in `main` and `neoforge` source trees on 2026-09-27 10:55:42 +08:00 (UTC+08:00) found eight unmatched pairs: `npc chicken`, `npc cow`, `npc pig`, `npc coppergolem`, `npc mannequin`, `npc sulfurcube`, `waypoints hpa` and `wp hpa`. The first six concern newer-version entity capabilities. The two HPA debugging aliases are now implemented and validated in the [native HPA follow-up](hpa-debugging-2026-10-03.md). Historical inventory evidence: `artifacts/command-inventory-2026-09-27.json`. The declaration scan does not validate parameter handling or runtime behavior.

## Command coverage

The known ordinary Minecraft 1.21.1 command groups and HPA debugging aliases on this checklist now have implementation follow-ups. HPA constructs an actual hierarchical portal graph against a loaded-chunk snapshot, searches it in the background and prints the refined path. It preserves existing navigation and waypoint state. This does not establish every command/provider/client combination or complete the broader Citizens goal.

Recent follow-ups cover [`powered`, `name` and `home` options](command-options-home-2026-09-28.md), [`armorstand` limb poses](armorstand-poses-2026-09-27.md), `follow`, `mount`, `pose`, `lookclose` / `look`, native command locations, removal targeting, text editing, entity/display commands and particle options. The command-options fixture passes 164 checks, including atomic validation, original duration/precedence, native powered admission and exact home navigation ownership. `horse --color` and `--colour` both exist; upstream's unused `minecart --item` parameter is not a missing implemented behavior.

## Behavior, data and integration acceptance

- [Blackboard reload replacement](behavior-memory-reload-2026-10-06.md) now removes stale native scalar/list entries absent from the incoming snapshot, with preparation failure preserving old contents. Ordinary NPC metadata transient policy is unchanged; custom-store loading remains provider-defined.

- [Blackboard key identity](behavior-memory-key-identity-2026-10-06.md) keeps built-in-name collisions in the string key space and preserves dotted names during metadata saving. Tests cover native and injected storage plus ordinary typed-key compatibility. Custom-store contracts and ambiguous legacy nested data remain separate scope.

- [Persistent blackboard lists](behavior-memory-lists-2026-10-05.md) now survive YAML save/load, including empty lists and null elements. Owned mutable copies isolate caller and snapshot state, and invalid list mutations cannot replace a previous save. Typed/string metadata-name interactions and custom-store acceptance remain open.

- [Behavior blackboard enumeration](behavior-memory-keys-2026-10-05.md) now exposes real key snapshots and clears native storage, including typed/session entries. Saving removes deleted keys from the owned data section. List persistence and typed/string metadata-name interactions still need their own acceptance before claiming complete blackboard support.

- [Behavior replacement preparation](behavior-replacement-2026-10-05.md) parses candidates strictly before removing a running tree. Unknown nodes and expression failures reject explicit replacement; empty containers remain valid. Native tests preserve old execution, blackboard identity and saved data after rejection. Custom factory side effects/controller reset failure remain separate concerns.

- [Behavior template input](behavior-template-input-2026-10-05.md) fixes short-form argument offsets and reports missing/unreadable files before attaching or modifying BehaviorTrait. Native parser coverage includes valid multiword filenames and rejected input preserving the target. Semantic tree replacement and provider side effects remain separate work.

- [Template workspace files](template-workspace-2026-10-05.md) normalize relative names and require regular direct-child files. Filesystem tests cover directories, missing/invalid entries and path scope; behavior fallback/provider execution remains separate coverage.

- [Template map merging](template-map-merge-2026-10-05.md) preserves explicit empty maps and prevents default-only nested/dotted replacements from overwriting scalar ancestors. Override-enabled nested replacements remain supported. Focused snapshot tests cover these merge rules.

- [Template generation](template-generation-2026-10-05.md) validates snapshots before saving and updates name/key indexes together. Overwrite preserves sibling templates, original source files and literal YAML keys, removes stale snapshot fields, and preserves disk/live state when snapshot capture fails. Both NeoForge versions pass 306 native creation checks including overwritten-template application. Partial YAML templates preserve unsaved target state through snapshot capture; arbitrary provider/client combinations remain separate acceptance work.

- [Template reload preparation](reload-templates-2026-10-05.md) validates a detached template collection before NPC publication. Invalid files retain old templates/NPCs/settings; repair and retry publish the new collection. Legacy migration disk effects and template application side effects remain separate work.

- [Staged skin cache on reload](reload-skin-cache-2026-10-05.md) preserves old cache objects and pending recipients until publication and restores them after preparation failure. Candidate generations never reactivate on later retries. Tests cover cache ownership without HTTP; live lookup completion and physical-client rendering remain separate acceptance work.

- [Reload session cleanup](reload-session-cleanup-2026-10-05.md) retains world editors and chat prompts through rejected shop preparation and closes them after new shop/NPC publication. Combined cleanup errors are retained without interrupting later cleanup categories; editor callbacks see the new registry. Physical-client interaction, skin-cache invalidation and arbitrary callback effects remain separate concerns.

- [Reload shop publication](reload-shop-publication-2026-10-05.md) checks and publishes shop maps before replacing the NPC registry. Stale preparation preserves old NPCs/settings; old-session cleanup errors still allow consistent new shop/NPC publication with aggregated errors. Editor closure, skin-cache invalidation and arbitrary provider effects remain separate concerns.

- [Reload settings recovery](reload-settings-2026-10-05.md) restores runtime values, duration caches and messaging configuration when candidate NPC preparation fails. Candidate loading sees new values; published registries keep them after cleanup errors. Both NeoForge versions pass 34 reload checks. Disk edits, arbitrary provider effects and complete shop publication transactionality remain separate concerns.

- [Permanent removal entity cleanup](permanent-removal-2026-10-05.md) completes native entity and registry cleanup even when despawn is canceled or throws, while reporting exceptions and preserving removal history. Native removal coverage includes these cases; custom NPC provider cleanup remains its own contract.

- [Bulk removal lifecycle](bulk-removal-lifecycle-2026-10-05.md) completes disposal across callback failures and reports the accumulated error after cleanup. - [Undo history callback boundaries](undo-history-2026-10-05.md) reject sender reentry and bound bulk undo to entries present at invocation.
