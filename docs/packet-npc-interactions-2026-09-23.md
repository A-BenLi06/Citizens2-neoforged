# Native interactions with packet NPCs

Scope follows [the Citizens and NeoForge ecosystem guidance](neoforge-ecosystem-replacements-2026-09-22.md). This changes Citizens entity interaction transport and its existing click-event path. Retained provider implementations remain in place.

## Behavior and implementation

Minecraft's incoming interaction handler originally resolved an entity ID only through ServerLevel.getEntityOrPart. Packet NPCs deliberately have no world entry, so their clicks never reached native interaction dispatch or Citizens events.

The required ServerGamePacketListenerMixin wraps that lookup after vanilla's server-thread check. Native resolution takes precedence. When no native target exists, PacketNPC resolves its lifecycle-owned integer-ID index and requires the current trait, current registry ownership, spawned/nonremoved entity, existing pairing, current PlayerList identity, live connection, matching dimension, configured tracking range and NPC/ancestor visibility. Hidden ordinary NPCs are also rejected at this boundary. Non-NPC targets retain native behavior.

The resolved virtual entity continues through vanilla's world-border check, attribute-driven interaction reach, item feature checks and packet action dispatch. The native NeoForge interaction/attack hooks then reach the existing Citizens click events and CommandTrait. Hand, hit position and secondary-action state retain their native meanings. Invalid attacks on item entities still invoke vanilla's disconnect policy; the implementation does not invent attacks for non-pickable helpers.

The index registers after virtual tracker creation and unregisters on despawn, trait replacement, removal, destruction and controller cleanup. Removal checks trait identity. Retired cleanup is idempotent so an old trait cannot discard a replacement's shared entity. A detached replacement explicitly releases its own tracker after despawn, because the controller can still belong to the older trait. Entries do not require scanning NPC registries for each incoming interaction.

Right-click deduplication previously remembered one global player/entity/tick tuple. Alice's and Bob's specific/generic packets could interleave and repeat Citizens events and commands. It also let a duplicate packet use a held item after the first event consumed the click. The shared handler now records the first result per player, target ID and server tick. Handled duplicates remain canceled; unhandled ones retain native fallback. An entry is reserved before event dispatch to prevent reentrant duplicate events. Weak identity player keys, integer target IDs and logout cleanup avoid retaining retired player/entity objects.

Minecraft reuses the old entity ID on player respawn, and Entity.equals compares that ID. Both tracker membership and click caching therefore use object identity. The runtime audit proves that a newly respawned player is initially unpaired and gets a separate click result after native pairing, even within the same tick as the old player's click.
