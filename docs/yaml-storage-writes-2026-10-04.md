# Atomic and ordered YAML storage writes

Implementation base: `1fccc20`. Target: Minecraft 1.21.1, NeoForge 21.1.233 and 21.1.248.

`YamlStorage` opened the destination before serializing, so a failing value getter could truncate a valid save to zero bytes. Independent asynchronous writes could also complete after newer synchronous saves, including across two storage instances addressing the same file. Reload had no barrier for pending writes, and binary arrays retained mutable caller references.

## Publication and ordering

Each save writes UTF-8 YAML and its commented header to a temporary sibling, flushes the writer, forces the file channel and atomically replaces the destination. Failures before replacement preserve the previous file and remove the temporary file. Unsupported atomic replacement is reported without falling back to truncation or deletion. New documents are published through the same path instead of creating an empty destination first.

Existing POSIX permissions, ACLs and DOS hidden/system flags are copied where supported. Read-only files and directory destinations are rejected. Existing symbolic links resolve to their target; a dangling link fails without replacing the link. This is not a guarantee of full crash durability or coordination with writers outside this JVM.

Pending writes are ordered by resolved file path across storage instances. Later requests wait for preceding ones, including failed requests, and a failure does not prevent retry. Synchronous serialization still runs on its caller's thread after waiting; asynchronous serialization runs in the common pool and reports failures. Reload waits for preceding requests and reads the last successfully published file. Recursive access to the same file during serialization is rejected. Completed queue entries are released without removing a newer request.

Snapshots detach maps, collections, sets and arrays and reject recursive collections/arrays before file mutation. Arbitrary custom Java beans are still serialized through their getters; this does not supply a general immutable object snapshot or make concurrent mutation of a storage document thread-safe.

The native store first publishes a complete in-memory NPC snapshot. If the subsequent YAML write fails, the old disk document survives and the complete new memory document remains available for retry. This extends the earlier [NPC snapshot transaction](npc-save-integrity-2026-10-04.md) and [delegate-construction handling](persistence-delegate-failures-2026-10-04.md).

## Validation

Ten focused write tests cover failed serialization, successful retry, synchronous/asynchronous ordering, failed preceding writes, ordering across storage instances, binary/list snapshot isolation, reload barriers, ACL/hidden-state preservation and read-only rejection, recursive serialization, cyclic arrays and caller-thread serialization. All ten and the eight existing round-trip tests pass.

The initial negative run reproduced four defects and one fixture error: node composition rejected the synthetic blocking bean's global tag before reaching the binary assertion. After permitting only that synthetic tag for composition, a second negative run reproduced the changed binary bytes and missing ordering across storage instances. The fixture error is not counted as production defect evidence.

The native save-integrity fixture adds ten actual-file checks to its previous 104. Normal and packet NPCs persist through real YAML storage; an injected failing value preserves the previous bytes, leaves a complete retryable memory snapshot and cleans temporary files. Retry and reload restore both NPC identities, packet transport, unknown data and the header. Both NeoForge versions pass 114 checks each, 228 total.

The provider absent/present/absent-again cycle passes 63/66/64 checks, 193 total. General regression passes 107 NPC assertions and 223 probes. All 287 ordinary tests and 100 Interactions tests pass without failures, errors or skips, followed by a successful default-version clean test/build. Every Gradle/server invocation terminated before the next began. Tested production, test and native-fixture hashes match the final source.

Release/source archives contain the built implementation and exclude audit classes. Citizens contains no Interactions implementation/resources/embedded JAR. Interactions contains no Citizens classes, and every entry name and content matches the `1fccc20` baseline; rebuilding can change ZIP metadata and the overall archive hash. The original Citizens save remains unchanged. Consolidated evidence: `artifacts/yaml-write-validation-summary.json`, generated by `artifacts/summarize-yaml-write.ps1`. Reproduce using [the native fixture instructions](../tools/save-integrity-runtime-audit/README.md) and a normal clean test/build.
