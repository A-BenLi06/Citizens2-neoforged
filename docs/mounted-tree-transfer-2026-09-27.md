# Mounted passenger-tree teleport

## Behavior and ownership

Teleporting a spawned Citizens NPC now finds its root vehicle and moves the complete native passenger tree, including sibling branches. The selected NPC's cancellable teleport event runs before mutation. Native dismount events run before any member moves. The coordinator keeps direct references to native replacements, restores the original relationships in native passenger order and retries refused remounts through the server scheduler. Same-world moves and cross-dimension round trips use the same ownership rules.

Each built-in NPC contributes its current controller, entity and teleport revision. A new teleport, mount request, trait replacement or removal supersedes the old operation. MountTrait pauses automatic remounting while the coordinator owns the tree, while explicit requests remain effective immediately. Releasing the pause adopts a different NPC vehicle selected directly by a native callback, without overwriting a newer explicit request. Interrupting one branch repairs untouched, still-owned edges in place when their endpoints remain in the same world; it does not move or remount superseded endpoints.

Ordinary entities use native copy/restore/admission and removal; actual players retain their native player object and connection. World and virtual NPCs preserve their existing ownership and tracking policy. The coordinator does not write passenger lists or native entity indexes directly. A refused first sibling is retried before appending later siblings, preserving passenger order.

## Admission, rollback and callbacks

A non-player source remains alive until the destination admits its candidate. Join listeners see the candidate bound to its real NPC owner. Rejection restores the original controller/entity relationship; if a later member is rejected, earlier successful moves are rolled back before remounting. Members whose detachment was refused are left intact. Previously detached siblings can return to their original position and vehicle. Exceptions propagate after recovery is attempted; a second recovery exception is retained as a suppressed exception.

A join listener can request another NPC teleport while its candidate is not yet admitted. The event and validation run normally, but the latest accepted move executes after admission or rollback resolves. This prevents a return to the source dimension from colliding with the source UUID that is intentionally still alive. Destruction/replacement takes precedence over both moves.

The NeoForge source places `EntityJoinLevelEvent` inside `PersistentEntitySectionManager.addEntity`, after `ServerLevel.addEntity` checks the removed flag. A listener can therefore destroy a candidate and still have it inserted into the destination index after the callback returns. The transfer explicitly retires an obsolete admitted candidate through its newly installed native removal callback. The retained diagnostic run demonstrates the destination-index orphan; its source entity and NPC had already been removed correctly.

## Validation

The dedicated isolated server passes **216 checks** on NeoForge **21.1.248**. The configured project default remains **21.1.233**. Coverage includes world/virtual cow and player NPC combinations; a root, nested rider and sibling branches; UUID, health, ownership and native indexes; same-world movement and round trips; ordinary boat roots; admitted synthetic player sessions as riders and root vehicles; cancellation before mutation and after partial detachment; rejected root/child admission; exception recovery; callback destruction and return transfers; explicit/direct mount supersession; untouched sibling repair; removal/new teleports during pending retries; and real-tick remount ordering without MountTrait owning the retries.

The fixture uses native player admission and protocol encoding with embedded connections. It is not a physical-client rendering test. Reproduce it with [the audit instructions](../tools/mount-transfer-runtime-audit/README.md). Logs retain the initial selected-leaf-only failure, the partially detached sibling failure, and the callback destruction/index failure. The final fixture intentionally throws one admission exception to test rollback and propagation; NeoForge logs that expected exception before subsequent passing assertions.

Final regression/build counts and source/archive hashes are recorded in `artifacts/mount-transfer-validation-summary.json`, generated by `artifacts/summarize-mount-transfer.ps1`. The root walkthrough records the completed gates and timestamp. Audit/provider source directories remain opt-in and must be excluded from a clean normal build's release and source jars.

## Limits and remaining work

The new coordinator covers built-in `CitizensNPC` instances and ordinary native entities in their tree. Trees containing another NPC implementation are rejected before detachment. The older `AbstractNPC` fallback remains unchanged; this is not a claim of arbitrary custom-controller parity. The reference helper visits a first-passenger chain; its existence is not evidence of a robust original retry loop or of support for all sibling branches.

Retries are owned by the current in-memory lifecycle, not persisted transactions across server restarts. Arbitrary modded entity transfer contracts and unrelated direct same-world teleports of ordinary entities during a pending retry are not certified by these checks. Physical-client seats/interpolation/targeting, dialogue input while riding, the complete provider/modpack stack and actual proxy arrival remain acceptance work. No production installation or original save data was modified. The broader [remaining command and acceptance checklist](remaining-citizens-work-2026-09-26.md) keeps the Citizens goal open.

Unmounted hologram helpers are outside a passenger tree. Source review identified a separate parent-dimension-following gap in their coordinate-only rendering helper; the current packet-hologram regression covers viewer dimension changes, not this parent transfer path. That native follow-up remains explicitly listed in the checklist.
