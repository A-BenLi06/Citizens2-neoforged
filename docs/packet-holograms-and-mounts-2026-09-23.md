# Packet holograms and native mounted hierarchies

This Citizens core follow-up implements the packet-hologram setting from the checked-in reference source. Scope remains governed by [the retained NeoForge ecosystem guidance](neoforge-ecosystem-replacements-2026-09-22.md); no provider is replaced.

## Configuration and behavior

`npc.use-packet-holograms` defaults to `false`, matching the reference. When enabled, newly created hologram helpers use PacketNPC transport: text and name helpers, native item anchors/passengers and item displays. Helpers remain temporary Citizens NPCs with the existing parent redirect, visibility, tracking and text contracts. They are absent from world entity storage.

The setting is read when a renderer creates its helpers. Existing helpers keep their transport until rebuilt; NPC respawn/reload creates replacements using the current setting. Setting it back to false restores ordinary world helpers on rebuild. Renderer choices, saved lines and existing provider implementations are retained. Name renderers continue to honor the reference's configured default-renderer override.

## Native pairing and positioning

Vanilla includes passenger lists in initial pairing bundles and subsequent tracker broadcasts. With virtual entities, a vehicle can be paired before its children or a child before its vehicle. Sending the complete server passenger list can therefore reference an entity the viewer has not received yet. Hidden helpers introduce the same problem.

PacketMounts records entity IDs at their actual native spawn packet within ServerEntity.addPairing. NPC mount packets are projected onto each viewer's already paired, currently eligible entities. Unknown vehicles defer their mount packet; native pairing of the missing endpoint supplies the relationship later. The visible passenger order is retained. Filtering creates a new packet and never changes the shared broadcast packet, the entity's passenger list or another viewer's result. Ordinary non-NPC mount packets retain native behavior.

The same projection runs for native world broadcasts, the direct player recipient in broadcastAndSend and EntityPacketTracker broadcasts. Native unpairing releases an ID before StopTracking callbacks can pair it again. Weak identity player keys, dimension checks and logout cleanup bound the pairing state; a respawned player cannot inherit stale state just because vanilla reused its entity ID.

Virtual passengers receive native vehicle attachment positioning before viewer reconciliation and packet updates. Virtual ancestor chains are positioned from the root outward, so registry iteration order does not leave a child at an old position. This invokes positionRider, not entity AI, physics or rideTick. ServerLevel.tickPassenger otherwise special-cases player subclasses and ticks them even outside world storage; its packet-entity branch now positions the rider and preserves native traversal of its children without simulating the virtual rider.

Tracker replacement unpairs viewers while preserving the live entity and its mount relationships. Despawn/removal still discards the entity. This distinction matters because native Entity.setRemoved detaches both the entity and its passengers; using discard to retire a tracker silently dismantled a mounted hierarchy.
