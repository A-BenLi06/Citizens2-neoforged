# Independent shop restoration during NPC undo

Removal history now snapshots the NPC's independent default shop definition as well
as the NPC itself. Stock editor sessions close before capture, so their committed
changes can enter the snapshot. Admission resumes afterward; closed screens do not
reopen if capture fails. No empty shop is created merely to capture history.

Undo strictly decodes a detached shop definition and rejects an occupied shop UUID
before creating the NPC. It publishes the definition before creation callbacks run.
The native restoration creation path retires failed runtime instances without
deleting persistent definitions. Cleanup removes only the expected shop binding,
preserves replacements/shared owners, and retires an unbound provisional definition.
Failed undo retains command history for retry.

Native testing exposed a separate serialization defect: reified objects containing
only default/key fields produced no entry, losing empty shop pages. Such present
objects now encode an empty map. A disk round-trip test covers page positions and
empty item entries.

Validation: 79 removal checks pass on each of NeoForge 21.1.233 and 21.1.248. The added scenarios cover
shop conflict preservation, canceled creation replacing the provisional shop,
registry cleanup and retry, detached definitions, private/global stock balances,
physical stock items, page structure, shop type and view permission. Clean ordinary
test/build passes with 354 tests and no failures, errors or skips. Native editor
coverage opens the private and global stock editors simultaneously, changes their
container slots, verifies the underlying stock is still unchanged, then deletes the
NPC. Both screens close and undo restores the buffered changes in both inventories.
This is server-side container coverage, not physical-client drag/drop validation.

Undo now uses a strict native snapshot-load path: missing traits, persistence errors
and exceptions from trait loading reject restoration rather than logging partial
success. Ordinary NPC loading retains its existing behavior. The scoped strict mode
still invokes native load overrides, including navigation and deferred spawn logic.
An unpositioned NPC's location is optional; strict loading must allow its valid
worldless snapshot. Native tests cover a throwing creation callback that replaces a
shop and a throwing trait load, cleanup, and retry restoring a non-default value.
They also deregister the saved trait provider before undo, verify rejection and
cleanup, and register it again before retrying the same preserved history entry.

This does not undo arbitrary external side effects of provider callbacks. Custom
registry providers still use their own create/destroy behavior. Deferred spawn
success and every provider-specific combination are not established by these checks.
Interactions remains a separate mod/JAR and has no production changes in this batch.
