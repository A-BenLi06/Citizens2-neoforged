# Independent shop restoration during NPC undo

Removal history now snapshots the NPC's independent default shop definition as well
as the NPC itself. Stock editor sessions close before capture, so their committed
changes can enter the snapshot. Admission resumes afterward; closed screens do not
reopen if capture fails. No empty shop is created merely to capture history.

Undo strictly decodes a detached shop definition and rejects an occupied shop UUID
before creating the NPC. It publishes the definition before creation callbacks run.
The native restoration creation path retires failed runtime instances without
deleting persistent definitions. Cleanup removes only the expected shop binding,
preserves replacements/shared owners, and retires an unbound provisional definition.
Failed undo retains command history for retry.

Native testing exposed a separate serialization defect: reified objects containing
only default/key fields produced no entry, losing empty shop pages. Such present
objects now encode an empty map. A disk round-trip test covers page positions and
empty item entries.

Validation: 71 removal checks pass on NeoForge 21.1.248. The added scenarios cover
shop conflict preservation, canceled creation replacing the provisional shop,
registry cleanup and retry, detached definitions, private/global stock balances,
physical stock items, page structure, shop type and view permission. Clean ordinary
test/build passes with 354 tests and no failures, errors or skips.

This does not establish full transactional loading of arbitrary traits: the existing
NPC load path can retain/log individual trait failures. Custom registry providers
still use their own create/destroy behavior. Native coverage of buffered editor
capture and throwing/load callback variants, plus the 21.1.233 runtime run, remains
follow-up work. These limits must not be described as a complete restoration audit.
Interactions remains a separate mod/JAR and has no production changes in this batch.
