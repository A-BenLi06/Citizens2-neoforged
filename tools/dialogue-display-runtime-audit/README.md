# Dialogue presentation audit

This opt-in audit runs only in `artifacts/dialogue-display-audit-server` on loopback port 25584. It uses connected server-player fixtures with outbound packet capture and refuses a fixture containing saved Citizens NPCs. It does not require or copy production player data.

Run with JDK 21:

```powershell
.\tools\prepare-dialogue-display-audit.ps1
Set-Location neoforge
.\gradlew.bat '-Pneo_version=21.1.248' -I ../tools/dialogue-display-runtime-audit.gradle runServer --console=plain
.\gradlew.bat '-Pneo_version=21.1.248' -I ../tools/audit-tests.gradle test --console=plain
.\gradlew.bat '-Pneo_version=21.1.248' test build --console=plain
```

The display portion has 127 checks: private boss-bar/nameplate/chat/ActionBar packets, simultaneous sessions and late joiners, styles/titles/progress, named empty rows and offsets, chat preservation, placeholder/control-token handling, unchanged option redraw, line/node replacement, manual timing, JSON components, rendering/action failure, range/dimension exits, logout/reload/shutdown and actual `PlayerList.respawn` rebinding. CHARACTER/WORD animation checks cover delay, Unicode, repeated spaces, initial/completion action counts, no redraw after completion and no restart during option selection. ActionBar checks cover the two status titles, twenty-tick refresh, disable/re-enable and cleanup. The packet entities are also checked to be absent from the world entity lookup. Twenty display/writer/inline unit cases cover configuration parsing, legacy bar styles, progress boundaries, title overrides, hologram geometry, component/style/control preservation, empty/multiline animation and inline settings; the complete dialogue unit suite has 93 cases.

Inline-choice cases exercise filtered positions, multiple markers and suffixes, hidden options, `start_options`, random/skipped terminal lines, movement/sneak selection, tenth options, normal/typed/original-alias input and actual packet commands through the dispatcher. Preview and ready views have distinct identifiers, so stale clicks cannot select an option after the list changes. Interruption cases verify exact action counts, node transitions, reward/preflight failures, command reentrancy, freed teleportation, actual player replacement and logout/reload/shutdown.

The same fixture now runs 91 additional native-action checks before the display suite. They inspect potion durations/levels/particles/icons and actual effect ticks; title timing/clearing/formatting; double-precision teleportation; registered/resource-pack sound packets and codec round trips; targeted/global sound stopping; native rocket components/movement; actual ordinary-player versus elevated command dispatch; saved-item/economy/shop interception boundaries; alias permissions; and failed preflight preserving payment. These checks have a separate `[NATIVEACTIONAUDIT] COMPLETE` marker.

The influence portion adds 61 checks with marker `[INFLUENCEAUDIT] COMPLETE`: signed bounds and legacy filename/player scope, native API and action preflight, cumulative/projected overflow, Unicode/quoted administration, NeoForge permission-handler grants/denials, JSON/text/condition/option placeholders, session initial/completion/option/interruption actions, fresh-store persistence and real-tick resumed updates/failures. Invalid influence commands must fail the actual command callback, stop later rewards and prevent saved progress; command preflight also checks grammar/target without rejecting a valid state established by an earlier native action. The scoped permission fixture wraps the active NeoForge handler and restores it afterward; it does not constitute a new actual-provider installation test. Five new unit cases cover record fidelity/corruption, integer boundaries, numeric requirements and command arguments.

After the synchronous checks, 84 scheduled-action checks advance on real server tick events using the production controller hooks. They verify independent dialogue/action clocks, exact wait and ActionBar deadlines, late failure/progress handling, option and interruption batches, real respawn/relogin identity, reload/logout/shutdown cancellation, long durations and ActionBar ownership/privacy. The marker is `[SCHEDULEDACTIONAUDIT] COMPLETE`. The dialogue unit suite also covers completion receipts and observer failure isolation.

The world phase runs after the scheduling/influence controllers stop. Its 89 checks exercise two actual datapack dimensions with the same path in different namespaces, native and original legacy world names, significant whitespace, missing/ambiguous destinations before payment, explicit alias precedence, malformed/replaced configuration, actual reload command cancellation and current alias state when delayed work resumes. It requires `[WORLDAUDIT] COMPLETE`. Eleven resolver unit tests also cover flattened-path collisions, canonical IDs, locale independence and immutable reload snapshots. The fixture's stored world name equals its folder basename; renamed-save behavior is verified by source inspection and explicit-name resolver tests, not by a renamed runtime fixture.
Chat assertions inspect outbound system-message packets, including legitimate command feedback generated by reward actions. Holograms display the complete body independently of animated chat. Native translation/keybind/score/NBT contents and next controls are indivisible animation units; CHARACTER otherwise advances by code point. Neither test fixture nor release code requires a separate animation scheduler.

The transfer phase adds 51 checks using `ConnectionType.OTHER` players with empty negotiated payloads. Actual register/unregister packets traverse the server listener; the checks verify exact opaque destination names and Java modified UTF bytes through the game codec, private dispatch, size/availability failures before payment, live revocation, delayed revalidation, reconnect isolation and session progress. It requires `[TRANSFERAUDIT] COMPLETE`. Six protocol unit tests cover the transfer payload. This verifies request emission and lifecycle behavior; arrival through a real proxy and second backend remains unverified.

The condition phase adds 39 checks for complete item/progress/native/brace operands, OR routing, literal `and`, lore containing operators, unknown or malformed predicates, corrupt progress and non-consuming removal spellings. Real sessions exercise all five requirement gates, including revocation after selection before payment, rewards or progress. It requires `[CONDITIONAUDIT] COMPLETE`. Ten grammar unit cases bring the complete dialogue suite to 93 tests, covering all fourteen operators, exact spacing/case, original interpretation order, unknown values, finite exact numbers and locale stability.

The source set is attached to `interactions`, and the Gradle gate requires all seven completion markers and no failure marker. Its timeout is three minutes. A normal build after an opt-in run removes the probes from release outputs; inspect jars for `RuntimeAudit` before delivering them.

These checks verify server state, vanilla packet content and recipient ownership. They are not a physical-client screenshot comparison of fonts, nameplate rendering or the original optional hologram providers.
